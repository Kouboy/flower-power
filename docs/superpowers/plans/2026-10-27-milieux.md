# Milieux (sous-projet 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Une partie avec un arc : 4 milieux de 3 pousses, chacun conclu par un niveau de boss (provisoire), puis saison 2 — v4.9.0.

**Architecture:** Les milieux sont des données (`FP.config.milieux`, `FP.palette.milieux`). Un bloc `state.run` porte la progression, écrit par `play/flow.js` seul. La génération lit le milieu pour ses familles d'obstacles ; le rendu lit `world.milieu` pour ses palettes ; un nouveau `ui/cards.js` dessine les cartons et l'écran de fin.

**Tech Stack:** JavaScript vanilla (modules IIFE sur `window.FP`), Canvas 2D, tests maison (`dev/check.html`, `node dev/run-checks.js </dev/null`, ~100 s).

**Spec:** `docs/superpowers/specs/2026-10-27-milieux-design.md` (partie « Sous-projet 1 »).

## Global Constraints

- Le jeu marche depuis `file://` ; aucun `getImageData` dans `src/ui` ; seul `audio/synth.js` crée des nœuds Web Audio.
- AGENTS.md : `index.html` ne reçoit que des lignes `<script>` (et le `<title>` de version) ; réglage → `config.js`, visuel → `render/*` ; pas de code mort (ce qui est remplacé est supprimé) ; fichiers < 400 lignes ; une entrée de CHANGELOG par version ; `dev/check.html` vert et une partie jouée.
- Ordre des milieux : `friche`, `industrie`, `decharge`, `nucleaire` ; noms « FRICHE URBAINE », « ZONE INDUSTRIELLE », « DÉCHARGE », « SITE NUCLÉAIRE ».
- Familles : friche `cone, scooter, tire, trashbag, drone` ; industrie `server, battery, solar, extinguisher, drone` ; décharge `microwave, arcade, trashbag, tire, scooter` ; nucléaire `nuclear, sarcophagus, battery, server` (+ T-Rex signature).
- Lignes satiriques et noms/ordres des boss : verbatim de la spec § 1.
- Aucune teinte de `FP.palette.danger` ni vert acide dans un décor de milieu ; la friche garde les palettes actuelles à l'identique.
- 3 pousses réussies par milieu ; une éclosion = +1 quel que soit le nombre de fleurs ; une mort ne change pas le cycle.
- Boutique : uniquement avant chaque niveau de boss et à la dernière chance ; `FP.config.shop.every` supprimé.
- Gains × `saison` (1, 2, 3…).
- Textes : seulement des glyphes de `ui/font.js` (on lui ajoute `«` `»`).
- Commits terminés par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Mort pendant le niveau de boss, puis dernière chance (boutique `last`) : on doit rester sur le niveau de boss du même milieu, sans avancer ni rouvrir une boutique « avant boss » en plus.
2. Éclosion à plusieurs fleurs (pollen) sur la 3ᵉ pousse : `level` saute de plusieurs crans, mais on entre une seule fois dans le boss.
3. Ancien enregistrement de records (`{ flowers, eco }` seulement) : le titre et le certificat s'affichent sans « undefined ».
4. Redimensionnement ou écran étroit (300 px) : les cartons les plus longs (« LE RÉACTEUR « NEUTRE EN CARBONE » ») tiennent à l'écran.
5. Changement de milieu : les caches de rendu (ciel, terre, ancrages des obstacles) se reconstruisent avec la nouvelle palette au lieu de garder l'ancienne.

### Task 3: Le cycle (pousses, boss, saison, boutique)

**Files:**
- Modify: `src/play/flow.js`, `src/play/shop.js` (en-tête), `src/core/config.js` (suppression `shop.every`), `dev/tests/shop.test.js:211`
- Test: `dev/tests/flow.test.js`, `dev/tests/milieux.test.js`

**Interfaces:**
- Consumes: `state.run`, `FP.config.run.steps`.
- Produces: transitions de `state.run` (seul `play/flow.js` les écrit) ; `state.run.card` = `{ kind: 'milieu' | 'boss' | 'victory', t0 }` ou `null` ; nouveau mode `'won'` (écran de fin) ; `FP.flow.continueAfterWin(state)`.

Règles (spec § 3) :
- Éclosion hors boss : `step += 1` ; si `step === steps` : `boss = true`, et la boutique s'ouvrira à la fin du fondu (`after: 'bloom'`) ; carton `boss` à la sortie de boutique.
- Éclosion du boss : `bosses += 1`, carton `victory` (pendant `bloom`) ; au passage fadeOut → fadeIn, **avant** `FP.level.generate` : `milieu += 1`, `step = 0`, `boss = false` ; si `milieu === 4` : `milieu = 0`, `saison += 1`, `won = true` (première fois seulement) ; carton `milieu`. À la fin du fondu : si on vient de finir une saison 1, mode `'won'`, sinon `ready`.
- `'won'` : un appui (`state.input.pressed`) après 1,5 s → `continueAfterWin` → `ready`.
- Mort : rien ne change ; boutique seulement si `reserves <= 0` (dernière chance).
- `card` est remis à `null` au lancement de la pousse (`germPop`), sauf `victory` qui s'efface à la fin du fondu.

- [ ] **Step 1: Tests** (simuler les éclosions avec un petit helper qui place la pointe à `surfaceY` et fait tourner `FP.flow.update` jusqu'au mode suivant ; `FP.shop.open` espionné) :
  - `flow: trois éclosions mènent au boss, boutique comprise` — après 3 éclosions : `run.boss === true`, boutique ouverte une fois (`after: 'bloom'`), carton `boss` en `ready`.
  - `flow: une mort ne fait pas avancer le milieu` — `step` inchangé, pas de boutique (réserves > 0).
  - `flow: une éclosion à plusieurs fleurs compte pour une pousse` — `score.flowerBonus = 2` : `step` +1, `level` +3.
  - `flow: battre le boss passe au milieu suivant` — `bosses 1`, `milieu 1`, `step 0`, `boss false`, `world.milieu === 'industrie'`, carton `milieu`.
  - `flow: après le 4ᵉ boss, écran de fin puis saison 2 en friche` — mode `'won'` ; un appui après 1,5 s → `ready`, `saison 2`, `milieu 0`, `won true`. Une 2ᵉ fin de saison ne repasse pas par `'won'`.
  - `flow: mort au boss puis dernière chance : on reste au boss` — (Review Focus 1) `boss` reste vrai, `milieu`/`step` inchangés, une seule boutique (`last`).
  - `flow: la boutique ne s'ouvre jamais hors boss et dernière chance` — 10 pousses mêlant morts et éclosions : chaque ouverture est `after: 'bloom'` avec `run.boss` vrai, ou `after: 'last'`.
- [ ] **Step 2:** Échec attendu.
- [ ] **Step 3: Implémenter** dans `flow.js` ; supprimer `shopDue` et `FP.config.shop.every` ; `shop.test.js:211` utilise `FP.config.run.steps`.
